# ΗΥ360 - Αρχεία και Βάσεις Δεδομένων
## Οργάνωση Δεδομένων

### 1. Αποθύκευση Δεδομένων
Μοντέρνες Βάσεις Δεδομένων είναι υπερβολικά μεγάλες για να αποθηκευτούν στην κύρια μνήμη, για αυτό ζούν συνήθως σε δευτερεύον αποθηκευτικό χώρο (σκληροί δίσκοι). Η απόδοση επηρεάζεται άμεσα από την οργάνωση των δεδομένων μέσα στον δίσκο με κύριο στόχο να είναι η ελαχιστοποίηση των δεδομένων που μεταφέρονται από τον δίσκο στην μνήμη. 

Σημειωγραφεία:
- **Καταγραφή (Record)**: αναπαράσταση μίας πλειάδας
- **Πεδίο (Field)**: Ξεχωριστό πεδίο με μία τιμή (String, int, float, etc) 
- **Αρχείο (File)**: Συλλογή από καταγραφές ίδιου τύπου
- **Block**: κομμάτι του δίσκου με προκαθωρισμένο μέγεθος και πολλαπλές καταγραφές

> Στην πραγματικότητα μία ΒΔ δεν είναι παρά μία συλλογή από καταγραφές κάθε μία με ίδιο αριθμό από πεδία με ίδιο όνομα και τύπο.

### 2. Two-Level Storage
Η φυσική μνήμη στην οποία αποθηκέυονται οι καταγραφές και τα αρχεία μπορούμε να την σκεφτούμε σαν έναν πίνακα από bytes.
Τα αρχεία όπως είπαμε αποθηκέυονται γενικά στον δευτερέυον αποθηκευτικό χώρο, και για να μπορέσουμε να εφαρμόσουμε λειτουργίες πάνω τους πρέπει πρώτα να τα μεταφέρουμε στην κύρια μνήμη.

#### Record Organization
Τα πεδία σε μία καταγραφή πρέπει να είναι δομημένα έτσι ώστε να μπορούμε να τα προσπεράσουμε, υπάρχουν δυο κατηγορίες:
- **Καταγραφές σταθερού μεγέθους**: εδώ άμα θέλουμε να τα προσπεράσουμε απλά 
- **Καταγραφές μεταβλητού μεγέθους**: Πιο περίπλοκες, χρειαζόμαστε παραπάνω πληροφορίες (length,pointers) για να εντοπίσουμε πεδία

#### Block Organization
Έχουν σταθερό μέγεθος, συνήθως $2^9 - 2^{12}$ bytes. 
Όταν μεταφέρουμε δεδομένα από τον δίσκο στην μνήμη το κάνουμε σε blocks, το κόστος μία λειτουργίας επηρεάζεται από **πόσα** blocks πρέπει να μεταφέρουμε. Έτσι άμα πολλαπλές καταγραφές από ένα αρχείο είναι στο ίδιο block μπορούμε να αυξήσουμε την απόδοση των λειτουργιών.

#### Buffering
Μπορούμε να κάνουμε buffering από blocks που χρησιμοποιούνται συχνά στην κύρια μνήμη για να αποφύγουμε την συχνή μεταφορά τους.

#### Pointers
Δείκτες χρησιμοποιούνται για να εντοπιστούν καταγραφές μέσα στον δίσκο, μπορούμε να τους αναπαραστήσουμε σαν έναν ζευγάρι `(b,k)` όπου `b` είναι το block και `k` είναι η τιμή από το κλειδί της καταγραφής που θέλουμε.

#### Pinned Records
**Οι καρφιτσωμένες καταγραφές (pinned records)** είναι εγγραφές σε μια βάση δεδομένων που δεν μπορούν να μετακινηθούν από τη θέση αποθήκευσής τους, επειδή υπάρχουν δείκτες (pointers) από άγνωστες τοποθεσίες που δείχνουν προς αυτές. Αυτές οι καταφραφές δυσκολέυουν πολύ την επεξεργασία τους εφόσον άμα θέλουμε να αλλάξουμε κάτι πρέπει να ενημερώσουμε όλους τους δείκτες τους οποίους δεν ξέρουμε.

#### Διαγραφή Καρφητσομένων Καταγραφών
**Το πρόβλημα της διαγραφής καρφιτσωμένων καταγραφών** προκύπτει όταν υπάρχουν δείκτες από άγνωστες τοποθεσίες που δείχνουν σε μία καταγραφή. Αν τη διαγράψουμε και απελευθερώσουμε τον χώρο της, και αργότερα αυτός ο χώρος χρησιμοποιηθεί για νέα καταγραφή, οι παλιοί δείκτες θα δείχνουν λανθασμένα στη νέα καταγραφή — αυτό ονομάζεται **"κρεμασμένος δείκτης" (dangling pointer)** και οδηγεί σε λάθη, καταστροφή δεδομένων ή και κατάρρευση του συστήματος. Για να το αποφύγουμε, χρησιμοποιούμε ένα **"deleted bit"** που σηματοδοτεί μια καταγραφή ως διαγεγραμμένη χωρίς να απελευθερώνουμε άμεσα τον χώρο της.

### 3. Additional bytes
Θα χρειαστούν επιπλεόν bytes για κάθε καταγραφή ώστε να μπορέσει να λειτουργήσει σωστά, συγκεκριμμένα:
- ένα ή περισσότερα μπορεί να χρειαστούν για το μέγεθος της καταγραφής
- ένα byte που περιέχει:
  - το bit καταγραφής
  - used/unused bit: για να δηλώσει αν θέση καταγραφής είναι κενή
- Ελευθερος χώρος: άχρηστα bytes μπορεί να χρησιμοποιηθούν για πιο πρακτικές θέσις μνήμης

Παράδειγμα: Αποθήκευση αριθμού
πεδία:
1. Αριθμός: integer, κρατάει τον αριθμό
2. Όνομα: ένα μοναδικό byte που κρατάει τον πρώτο χαρακτήρα του ονόματος
3. Τετράγωνο: integer, κρατάει το τετράγωνο του αριθμού

Άν ένας ακέραιος integer χρειαζεται 4 bytes θα χρειαστούμε συνολικά 9 bytes για την καταγραφή του, επιπλέον θα χρειαστόυμε ένα deleted bit, used/unused bit και empty space
