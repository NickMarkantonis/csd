# ΗΥ360 - Αρχεία και Βάσεις Δεδομένων
## SQL
### 1. Εισαγωγή στην SQL
- **Βασικά Χαρακτηριστικά:**
	- Είναι η πιο ευρεώς χρησιμοποιούμενη γλώσσα για Σχεσιακές Βάσεις Δεδομένων
	- Βασίζεται εννοιολογικά στον **Σχεσιακό Λογισμό** (και έχει την ίδια εκφραστική δύναμη με την Άλγεβρα και τον Ασφαλή Λοιγσμό)
	- Παρέχει δομές για **Ορισμός Δεδομένων (DDL)** και **Χειρισμό Δεδομένων (DML)**
- **DDL - Data Definition Language:**
	- `CREATE TABLE`: Δημιουργεί έναν νέο πίνακα (σχέση) με τα γνωρίσματα και τους τύπους δεδομένων τους.
	  Πχ.
	  ```sql
		create table customer(
			cid char(4) not null, 
			cname varchar(13), 
			city varchar(20), 
			discnt real
		);
		```
	- `ALTER TABLE`: Τροποποιεί τη δομή ενός υπάρχοντος πίνακα (προσθήκη/διαγραφή γνωρίσματος)
	  Πχ.
	  ```sql
		alter table customer add age int not null;
	    ```
	- `DROP TABLE`: Διαγράφει έναν πίνακα
	  Πχ.
	  ```sql
		drop table customer;
	    ```
- **DML - Data Manipulation Language (Βασική Δομή SELECT)**
	- `SELECT [ ALL | DISTINCT ] expression1, expression2, ...`
	- `FROM table1 [allias1], table2 [allias2], ...`
	- `WHERE condition;`
	- Η SQL είναι **δηλωτική**: ο χρήστης περιγράφει τι θέλει, όχι πώς να το πάρει
### 2. Εμφωλευμένες Επερωτήσεις
- **Βασική Ιδέα:** Μία εντολή `SELECT` (ονομαζόμενη *subquery* ή *subselect*) μπορεί να εμφανίζεται μέσα σε μια άλλη εντολή `SELECT`, κυρίως στην πρόταση `WHERE`.
- **Περιορισμός:** Μια σχέση στην πρόταση `FROM` πρέπει να είναι υπάρχων πίνακας **όχι** το αποτέλεσμα μία `SELECT`.
### 3. Κατηγορήματα για Έλεγχο Συνθήκων
Τα subqueries χρησιμοποιούνται με ειδικά κατηγορήματα για να ελέγξουν συνθήκες
- `IN`/`NOT IN`:
	- Ελέγχει αν μια τιμή ανήκει (ή δεν ανήκει) στο σύνολο των αποτελεσμάτων του subquery
	- Ισοδύναμο με το κατηγόρημα μέλους $\in$ στη θεωρία συνόλων
	- Παραδείγματα:
	  ```sql
	    select cid from Orders where aid in ( 
		    select aid from agents 
		    where city = 'NY' or city = 'Dallas'
		)
		```
		Ο παραπάνω κώδικας μπορεί να μεταφραστεί ώς εξής:
		"*Βρες τους κωδικούς πελατών που έχουν κάνει παραγγελίες μέσω πρακτόρων από τη Νέα Υόρκη ή το Ντάλας*"
- `EXISTS`/`NOT EXISTS`:
	- Ελέγχει αν το αποτέλεσμα του subquery είναι μή κενό
	- Πολύ ισχυρό κατηγόρημα, το `NOT EXISTS` είναι θεμελιώδες για την έκφραση πιο σύνθετων πράξεων, όπως η διαίρεση 
- Σύγκριση με Ποσοδείκτες (`ΑΝΥ`/`ALL`)
	- `expr θ ANY (subquery)`: Αληθές αν η σύγκριση `θ` είναι αληθής για **τουλάχιστον ένα** στοιχείο του subquery. (Το `= ANY` είναι ισοδύναμο με το `IN`)
	- `expr θ ALL (subquery)`: Αληθές αν η σύγκριση `θ` είναι αληθής για όλα τα στοιχεία του subquery (Το `<> ALL` είναι ισοδύναμο με το `NOT IN`)
### 4. Εκφραση Θεωρητικών Πράξεων
- **Διαφορά (R-S):** Μπορεί να εκφραστεί χρησιμοποιώντας `NOT EXISTS`. Η ιδέα είναι: "Επέλεξε τις πλειάδες της R για τις οποίες **δεν υπάρχει** ίδια πλειάδα στην S"
- **Διαίρεση:** Η SQL δεν έχει ειδικό τελεστή για την διαίρεση. Εκφράζεται με δύο ένθετα `NOT EXISTS
	- **Βασική Λογική:** "Βρές ολα τα x για τα οποία **δεν υπάρχει** y στο διαιρέτη τέτοιο ώστε να μην υπάρχει η σχέση (x,y) στον διαιρετέο"
	- Αυτή η δομή βασίζεται στην λογική ισοδυναμία: $\forall x ~ P(x) \equiv \lnot \exists x ~ \lnot P(x)$  
### 5. Τελεστής `Union`
- **Σκοπός:** Συνδυάζει τα αποτελέσματα δύο ή περισσότερων ερωτημάτων που έχουν **συμβατά σχήματα** (ίδιος αριθμός και τύπος στηλών)
- **Σύνταξη:** `subquery1 UNION [ALL] subquery2`
- Το `UNION` αφαιρεί τα διπλότυπα. Το `UNION ALL` τα διατηρεί
### 6. Συναρτήσεις Συνάθροισης (Aggregate Functions)
- **Βασικές Συναρτήσεις:** `COUNT`, `SUM`, `AVG`, `MAX`, `MIN`
- **Περιορισμοί Εφαρμογής:**
	- `COUNT`: Μπορεί να εφαρμοστεί σε οποιονδήποτε τύπο δεδομένων
	- `SUM`,`AVG`: Εφαρμόζονται **μόνο** σε αριθμητικούς τύπους
	- `MAX`,`MIN`: Εφαρμόζονται σε αριθμητικούς και αλφαριθμητικούς τύπους
- **Χειρισμός Διπλότυπων:** Η `COUNT(DISTINCT column)` μετρά μόνο τις διακριτές τιμές
- **Σημαντικός Περιορισμός:** Οι συναρτήσεις συνάθροισης **δεν μπορούν** να χρησιμοποιηθούν απευθείας στην `WHERE`. Για σύγκριση με το αποτέλεσμα τους, πρέπει να χρησιμοποιηθεί **εμφωλευμένο ερώτημα**.
### 7. Κενές Τιμές
- **Ορισμός και Σημαισολογία:** 
	- Μία κενή τιμή (`NULL`) είναι μια ειδική σταθερά που αντιπροσωπέυει μια τιμή που είτε δεν είναι γνωστή, είτε δεν έχει νόημα
	- Τα περισσότερα ΣΔΒΔ δεν κάνουν διακριση μεταξύ των δύο αυτών ερμηνειών
- **Συμπεριφορά σε Συνθήκες:**
	- Το αποτέλεσμα οποιασδήποτε σύγκρισης (πχ. $=$, $<$, $>$, ...) με μία κενή τιμή δεν είναι `TRUE` ή `FALSE` αλλά `UNKNOWN` 
	- Η λογική συνέπεια της SQL γίνεται **τριμερής** (`TRUE`, `FALSE`, `UNKNOWN`)
	- **Συνέπεια:** μια συνθήκη όπως `discnt <= 10 OR discnt > 10` μπορεί αν επιστρέψει `UNKNOWN` αν το `discnt` είναι `NULL`. Επομένος η πλειάδα δεν θα συμπεριληφθεί στο αποτέλεσμα.
- **Έλεγχος για κενές τιμές:**
	- Για να εντοπιστούν οι κενές τιμές, χρησιμοποιείται το ειδικό κατηγόρημα `IS NULL` 
	- Πχ. 
		```sql
		SELECT * FROM customers WHERE discnt IS NULL;
		```
- **Αλληλεπίδραση με Συναρτήσεις Συνάθροισης:**
	- Οι κενές τιμές αγνοούνται από τις συναρτήσεις συνάθροισης (`COUNT`, `SUM`, `AVG`)
	- H `COUNT(*)` μετρά όλες τις πλειάδες, αλλά η `COUNT(column_name)` μετρά μόνο τις μή-κενές τιμές της στήλης
	- Αν μία συνάρτηση συννάθροισης (εκτός την `COUNT()`) εφαρμοστεί σε ένα σύνολο μόνο με τιμές `NULL`, τότε επιστρέφει `NULL`
### 8. Ομαδοποίηση Δεδομένων (`GROUP BY`)
- **Σκοπός:** Ομαδοποιεί τις πλειάδες ενός πίνακα με βάση τις τιμές ενός ή περισσότερων γνωρισμάτων.
- **Σύνταξη:** 
  ```sql
	SELECT ... FROM ... GROUP BY column1, column2, ...
	```
- **Κανόνας συνέπειας:** Κάθε στήλη που εμφανίζεται στη λίστα `SELECT` **πρέπει** να περιλαμβάνει και στον όρο `GROUP BY`. Αυτό εξασφαλίζει ότι κάθε ομάδα έχει μοναδική τιμή για αυτή τη στήλη.
- **Σειρά εκτέλεσης:** Το `GROUP BY` εφαρμόζεται **μετά** το `WHERE` και **πρίν** το `SELECT`
### 9. Φιλτράρισμα Ομάδων (`HAVING`) 
- **Σκοπός:** Φιλτράρει τις ομάδες που δημιουργήθηκαν από το `GROUP BY`, με βάση τη συνθήκη που αφορά το συνολικό αποτέλεσμα της ομάδας.
- **Σύνταξη:** `GROUP BY ... HAVING condition`
- **Διαφορά από το `WHERE`:** 
	- Το `WHERE` φιλτράρει **μεμονωμένες πλειάδες πρίν** από την ομαδοποίηση
	- Το `HAVING` φιλτράρει **ολόκληρες ομάδες μετά** την ομαδοποίηση
### 10. Περιορισμοί Ακεραιότητας (Integrity Constraints)
Σκοπός είναι να διασφαλιστεί η ορθότητα και η συνέπεια των δεδομένων
- **Περιορισμοί Πεδίου (Domain Constraints):**
	- Εξασφαλίζουν ότι οι τιμές ενος γνωρίσματος ανήκουν σε ένα έκγυρο σ0ύνολο τιμών
	- Υλποιούνται με τους τύπους δεδομένων, το `CHECK` και το `NOT NULL`
