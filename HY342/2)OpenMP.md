## HY342 - Παράλληλος Προγραμματισμός
### Parallel programming in OpenMP

## Εισαγωγή στο OpenMP
Το OpenMP (Open Multi-Processing) είναι ένα πρότυπο API για την ανάπτυξη παράλληλων εφαρμογών που βασίζονται σε κοινή μνήμη. Υποστηρίζεται απο τα τις γλώσσες C, C++ και Fortran και αποτελείτε από:
- **Compiler Directives** (π.χ `#pragma omp parallel`)
- **Run-Time Routines** (π.χ `omp_get_thread_num()`)
- **Enviroment Variables** (π.χ `OMP_NUM_THREADS`)
Το OpenMP δεν είναι κατάλληλο για προγραμματισμό με κατανεμημένες μνήμες, δεν είναι ομοιόμορφα υλοποιημένο σε όλα τα συστήματα, δεν εγγυάται αποδοτική χρήση της μνήμης, δεν ελέγχει για εξαρτήσεις/data races/συγχρονισμό etc και τέλςο δεν μπορεί να χειριστεί I/O.

### Παράδειγμα:
for με ανεξάρτητες επαναλήψεις:
```c
for (i = 0; i < n; i++)
  c[i] = a[i] + b[i];
```
for με παράλληλες επαναλήψεις σε OpenMP
```c
#pragma omp parallel for shared(n, a, b, c) private(i)
for (i = 0; i < n; i++)
  c[i] = a[i] + b[i];
```

## Συντακτικό του OpenMP
Οι περισσότερες δομές του OpenMP είναι compiler directives. Οι δηλώσεις των συναρτήσεων και των τύπων βρίσκονται στο αρχείο `omp.h`. Οι οδηγίες αυτές εφαρμόζονται σε structured code blocks, δηλαδή τμήματα κώδικα με ένα μοναδικό σημείο εισόδου και ένα μοναδικό σημείο εξόδου. Επιτρέπεται επίσης η έξοδος μέσω της εντολής `exit()`.

### Γενική μορφή compiler directive στο OpenMP:
```c
#pragma omp construct [clause [clause] ...]
```
Όπου:
- `construct` είναι η δομή που καθορίζει την παράλληλη εκτέλεση (π.χ., `parallel`, `for`, `sections`).
- `clause` είναι προαιρετικές ρυθμίσεις που επηρεάζουν τη συμπεριφορά της δομής (π.χ., `private`, `shared`, `schedule`).

## Βασικές Έννοιες του OpenMP
### Fork-Join Μοντέλο
Το OpenMP χρησιμοποιεί το fork-join μοντέλο παραλληλισμού:
- **Fork**: Το κύριο thread (master) δημιουργεί πολλαπλά worker threads όταν εισέρχεται σε parallel region
- **Join**: Τα threads τερματίζουν όταν ολοκληρώσουν το έργο τους, και το πρόγραμμα συνεχίζει σειριακά
### Parallel Region
Ένα τμήμα κώδικα που εκτελείται ταυτόχρονα απο πολλά threads:
```c
#pragma omp prallel
{
    printf("Hello from thread %d\n", omp_get_thread_num());
}
```
#### Χαρακτηριστικά Parallel Regions:
Paralllel Regions: block κώδικα που εκτελείτε απο όλα τα threads ταυτόχρονα
- Το master thread έχει ID = 0
- Ο αριθμός των threads μπορεί να αλλάξει μόνο μπαίνοντας σε parallel region
- Τα prallel regions μπορεί να είναι φωλιασμένα αλλα δεν είναι εγκυημένο ότι θα εκτελεστούν έτσι
- Μπορεί με την χρήση ενός `if` να γίνει παραλληλισμός υπό προϋποθέσεις ή κώδικας που εκτελείται σειριακά

## Στοιχεία του OpenMP
### Τεχνικές ανάπτυξης παράλληλων εφαρμογών
Το OpenMP παρέχει διάφορες δομές και τεχνικές για την ανάπτυξη παράλληλων εφαρμογών, οι βασικές είναι
1. **Directives (Οδηγίες μεταγλώττιστή)**
  Επιτρέπουν τον έλεγχο της συμπεριφοράς του openMP μέσα στον κώδικα
2. **Parallel Regions (Παράλληλες περιοχές)**
  - `if(condition)`: Εκτελεί το παράλληλο region μόνο αν η συνθήκη είναι αληθής
  - `num_threads(N)`: Ορίζει τον αριθμό των threads που θα εκτελέσουν το region
3. **Work Sharing (Μοίρασμα εργασίας)**
  Χρησιμοποιείται για την διαμοίραση εργασίας μεταξύ των threads
4. **Synchronization (Συνγχρονισμός)**
  Περιλαμβάνει μηχανισμούς όπως `critical`, `atomic`, `barrier`, `ordered` για την αποφυγή data races και την εξασφάληση σωστής εκτέλεσης
5. **Data-Sharing attributes (Κατανομή Μνήμης)**
  - `private`: Κάθε thread έχει τοπική μεταβλητή
  - `firstprivate`: Ιδιότητες του `private` αλλα με αρχικοποίηση
  - `lastprivate`: Ιδιότητες του `private` αλλα αποθυκέυει την τελική τιμή της μεταβλητής μετά την εκτέλεση του parallel region
  - `shared`: Όλα τα threads έχουν πρόσβαση στην ίδια μεταβλητή
  - `reduction`: Συνδυασμός πολλών τοπικών μεταβλητών σε μία κοινή (π.χ άθροισμα)
  - `threadprivate`: Ιδιοότητες `private` αλλα διατηρείται η τιμή μεταξύ διαφορετικών parallel regions
  - `copyin`: Χρησιμοποιείται για αρχικοποίηση `threadprivate` μεταβλητών

### Enviroment Variables
Στο OpenMP υπάρχουν μεταβλητές που επιτρέπουν τη διαμότφωση της εκτέλεσης του πρόγράμματος. Αυτές ρυθμίζονται είτε μέσα στον κώδικα είτεε μέσω του περιβάλλοντος του λειτουργικού συστήματος, συγκριμμένα μπορούμε να αλλάξουμε:
1. **Number of Threads**
  Καθορίζουμε πόσα threads μπορούν να χρησιμοποιηθούν
    ```c
    export OMP_NUM_THREADS = 4
    ```
2. **Scheduling Algorithm** 
  Ελέγχει πώς κατανέμονται οι επαναλήψεις των loops στα threads, παίρνει τις τιμές: `static`, `dynamic`, `guided`, `runtime`
    ```c
    export OMP_SCHEDULE = "dynamic,4"
    ```
3. **Dynamic Thread Adjustment**
  Επιτρέπει στο OpenMP να προσαρμόζει δυναμικά τον αριθμό των threads
    ```c
    export OMP_DYNAMIC = true
    // ή
    omp_set_dynamic(1);
    ```
4. **Nested Parallelism**
  Επιτρέπει τη δημιουργία parallel regions μέσα σε parallel regions
    ```c
    export OMP_NESTED = true
    // ή
    omp_set_nested(1);
    ```

### Runtime Enviroment
Το **Runtime Enviroment** του OpenMP παρέχει λειτουργίες για:
1. **Διαχείριση Threads**:
  - `omp_get_num_threads()`: Επιστρέφει τον αριθμό των ενεργών threads.
  - `omp_get_thread_num()`: Επιστρέφει το ID του thread.
  - `omp_set_num_threads(N)`: Ορίζει τον αριθμό των threads.
  - `omp_get_max_threads()`: Επιστρέφει το μέγιστο επιτρεπτό αριθμό threads.
2. **Δυναμική Ρύθμιση Threads**:
  - `omp_set_dynamic(int)`: Ενεργοποιεί/Απενεργοποιεί τη δυναμική ρύθμιση threads.
  - `omp_get_dynamic()`: Επιστρέφει αν είναι ενεργοποιημένη η δυναμική ρύθμιση.
3. **Nested Parallelism (Φωλιασμένος Παραλληλισμός)**:
  - `omp_set_nested(int)`: Ενεργοποιεί/Απενεργοποιεί την εμφωλευμένη δημιουργία parallel regions.
  - `omp_get_nested()`: Επιστρέφει αν είναι ενεργοποιημένος ο εμφωλευμένος παραλληλισμός.
4. **Χρονισμός & Locks**:
  - `omp_get_wtime()`: Υπολογίζει τον χρόνο εκτέλεσης σε δευτερόλεπτα.
  - `omp_init_lock()`, `omp_set_lock()`, `omp_unset_lock()`, `omp_destroy_lock()`: Χρησιμοποιούνται για αποκλειστική πρόσβαση σε κρίσιμες περιοχές μνήμης.

### Multi-threading και κοινή Μνήμη
Στο OpenMP τα threads επικοινωνούν μεταξύ τους μέσω κονής μνήμης, στην οποία μπορούν να γράφουν και απο την οποία μπορούν να διβάζουν δεδομένα, δημιουργούνται έτσι προβλήματα όπως τα race conditions, όμοια όπως είδαμε και στα pthreads. Για να το αντιμετοπίσουμε αυτό χρησιμοποιούμε διάφορουν μηχανισμούς συγχρονισμού και πρόσβασης μνήμης:

#### Συγκχρονισμός
Ο Συγχρονισμός των threads είναι κρίσιμος για την αποφυγή προβλημάτων πρόσβασης στην μνήμη. Υπάρχουν διάφορες τεχνικές συγχρονισμού, όπως οι barriers, οι locks, και άλλοι μηχανισμοί που διασφαλίζουν ότι η εκτέλεση των threads ακολουθεί μία συγκεκριμμένη τάξη και δεν επηρεάζεται από ασυντόνιστες προσβάσεις στην μνήμη. Παρόλα αυτά, ο συγχρονισμός μπορεί να έχει υψηλό κόστος σε απόδοση, καθώς οι καθυστερήσεις που εισάγονται από ανάγκη διαχείρισης της αλληλεπίδρασης των threads μπορούν να επιβραδύνουν την εκτέλεση του προγράμματος.

#### Βελτιστοποίηση πρόσβασης στη μνήμη 
Δεδομένουν ότι ο συγχρονισμός είναι ακριβός το OpenMP παρέχει directives που ελέγχουν την πρόσβαση στη μνήμη και μειώνουν την ανάγκη για συγχρονισμό, βελτιώνοντας έτσι την απόδοση του προγράμματος. Η σωστή χρήση αυτών των directives μπορεί να βοηθήσει στην ελαχιστοποίηση των περιττών καθυστερήσεων και στην αποετελεσματικότερη αξιοποίηση των πόρων του συστήματος.

## Προγραμματιστικό Μοντέλο / Κατανομή εκτέλεσης σε threads:
Η εκτέλεση του κώδικα μοιράζεται σε όλα τα threads και πρέπει να βρίσκεται μέσα σε ένα parallel region. Ο κώδικας είτε θα εκτελεστεί από όλα τα threads της ομάδας είτε από κανένα. Κατά την έναρξη δεν υπάρχει barrier, μόνο κατά τη λήξη, εκτός αν υπάρχει η ρύθμιση nowait, η οποία παραλείπει το barrier. Επιπλέον, οι δομές παραλληλισμού δεν δημιουργούν νέα threads, αλλά εκτελούνται από τα υπάρχοντα. Για λόγους απόδοσης και απλότητας, είναι προτιμότερο οι δομές που απαιτούν παράλληλη εκτέλεση να ξεκινούν μαζί με το parallel region, ώστε να αποφεύγονται περιττά κόστη συγχρονισμού και δημιουργίας νέων threads.

## Η δομή `Reduction`
Η δομή reduction καθορίζει τον τρόπο με τον οποίο πολλά αντίγραφα μιας τοπικής μεταβλητής που δημιουργούνται από διαφορετικά threads συνδυάζονται σε μία τελική τιμή, η οποία θα αποθηκευτεί στη μεταβλητή του master thread στο τέλος της εκτέλεσης. Το συντακτικό της είναι το εξής:
```c
reduction (operator: variable list)
```
Οι μεταβλητές που περιλαμβάνονται στη λίστα δηλώνονται αυτόματα ως `private` για κάθε thread. Ο `operator` μπορεί να είναι μία από τις εξής πράξεις: `+`, `*`, `-`, `&`, `|`, `^`, `&&`, `||`. Αν χρησιμοποιηθεί η οδηγία `ordered`, οι πράξεις θα εκτελεστούν με τη σειρά που θα είχαν εκτελεστεί σειριακά.


## Παράδειγμα υπολογισμός του $\pi$
Υπολογισμός του $\pi$ με τον αλγόρυθμο [Monte Carlo](https://en.wikipedia.org/wiki/Monte_Carlo_algorithm) και OpenMP:
```c
#pragma omp parallel default(private) shared (npoints) reduction(+: sum) num_threads(8)
{
    int num_threads = omp_get_num_threads();
    int sample_points_per_thread = npoints / num_threads;
    int sum = 0;
    
    for (int i = 0; i < sample_points_per_thread; i++) {
        double rand_x = (double)rand() / RAND_MAX;
        double rand_y = (double)rand() / RAND_MAX;
        
        if ((rand_x * rand_x + rand_y * rand_y) <= 1.0) {
            sum++;
        }
    }
}
```

## Συγχρονισμός 
Το OpenMP παρέχει μηχανισμούς για συγχρονισμό των threads και διαχείριση της μνήμης.
- **single/master**: Υπολογισμός που εκτελείται από ένα μόνο thread
- **Patterns επικοινωνίας**: Τρόποι οργάνωσης της ανταλλαγής δεδομένων και συγχρονισμού μεταξύ threads, ώστε να επιτυγχάνεται αποδοτική κατανομή της εργασίας και αποφυγή συγκρούσεων στη μνήμη.
  - Reduction
  - Synchronized structures

### Δομές Συγχρονισμού
- **critical**: Επιτρέπει μόνο σε ενα thread να εκτελεί κρίσιμο τμήμα κώδικα
    ```c
    float res;
    #pragma omp parallel
    {
        float B;
        int i, id, NumThreads;
        id = omp_get_thread_num();          /* get the current thread ID */
        NumThreads = omp_get_num_threads()  /* get the number of threads */
        for (i = id; i < NumIter; i+=NumThreads)
            B = big_job(i);     /* Big Jobs running in parallel */
        #pragma omp critical
            consume(B,res);     /* Only one thread at the time performs this */
    }
    ```
- **atomic**: Μόνο για εγγραφή στη μνήμη, πιο γρήγορο από το critical.
    ```c
    #pragma omp parallel
    {
        double tmp, B;
        B = doit();         /* parallel */
        tmp = big_ugly(B);  /* parallel */
        #pragma omp atomic
            X += tmp;   /* One thread at the time */
    }
    ```
- **barier**: **Όλα** τα threads σταματούν σε αυτό το σημείο πρίν προχωρήσουν
    Πολλά constructs έχουν ήδη ένα barrier στο τέλος τους, δεν χρειάζεται δηλαδή να το δηλώσουμε
    Τα constructs αυτά είναι τα:
    - `#pragma omp parllel`
    - `#pragma omp for` (εκός άμα έχουμε το `nowait` στο τέλος)
    - `#pragma omp selections`
    ```c
    #pragma omp for
    for (i = 0; i < N; i++)
        a[i] = c[i] + b[i];
    /* -- implicit barrier -- */
    pragma omp for nowait
    for (i = 0; i < N; i++)
        d[i] = a[i] + b[i];
    /* -- no barrier here -- */
    ```
    Μπορούμε προφανώς να βάλουμε και εμείς barrier όπου θέλουμε με την εντολή: `#pragma omp barrier`
- **ordered**: Επιβάλλει σειρά εκτέλεσης μεταξύ των threads
    Επιτρέπει παράλληλη εκτέλεση αλλά η εκτύπωση γίνεται με τη σωστή σειρά
    Χρησιμοποιείται μόνο μέσα σε `#pragma omp for ordered`
- **locks**: Χαμηλού επιπέδου συγχρονισμός, όπως στα pthreads
    - `omp_init_lock(&lock)`: Αρχικοποίηση lock
    - `omp_set_lock(&lock)`: Επιτρέπει μόνο σε ένα thread να εκτελέση την κρίσιμη περιοχή
    - `omp_unset_lock(&lock)`: Απελευθέρωση κλειδώματος
    - `omp_destroy_lock(&lock)`: Καταστροφή lock
- **flush**: Διασφαλίζει οτι όλες οι εγγραφές στη μνήμη είναι σε όλα τα threads

## Παράδειγμα Sections
Κομμάτια κώδικα που θα εκτελεστούν παράλληλα, απο 1 thread το κάθε ένα
```c
#pragma omp parallel default (none) shared(n,a,b,c,d) private(i)
{
  #pragma omp sections nowait /* Προσοχή στον πληθυντικός */
  {
    #pragma omp section
    for (i=0; i<n-1; i++)
      b[i] = (a[i] + a[i+1]) / 2;
      
    #pragma omp section
    for (i=0; i<n; i++)
      d[i] = 1.0/c[i];
  }
}
```

## Χρήση `single` και `master`
- `single`: Εκτελείται από ένα μόνο thread, χωρίς barrier στην είσοδο/έξοδο
    ```c
    #pragma omp single [clause[[,] clause] ...]
    {
        // code
    }
    ```
- `master`: Εκτελείται μόνο απο το master thread, χωρίς *implicit barrier*
    ```c
    #pragma omp master [clause[[,] clause] ...]
    {
        // code
    }
    ```
Χρησιμέουν σε κώδικα που πρέπει να τρέξει σε έναν επεξεργαστή π.χ I/O

## Sceduling (Κατανομή Εργασίας)
Το Scheduling στο OpenMP αναφέρεται στον τρόπο κατανομής των επαναλήψεων μιας παράλληλης περιοχής (`for`) σε διαφορετικά threads. Το OpenMP περέχει διάφορους αλγόριθμους scheduling για την κατανομή των εργασιών (worksharing), συγκεκριμμένα:
- **static** `schedule(static, [chunk])`: Η κατανομή επαναλήψεων γίνεται *στατικά* κατα τον χρόνο μεταγλώττισης. Οι επαναλήψεις χωρίζονται σε κομμάτια και κάθε thread αναλαμβάνει ένα απο αυτά τα κομμάτια
    - Ο αριθμός των επαναλήψεων ανά thread είναι ίσως προκαθορισμένος 
    - Εάν δεν ορίσετε την παράμετρο `chunk`, τότε κάθε thread αναλαμβάνει τον ίδιο αριθμό επαναλήψεων
- **dynamic** `schedule(dynamic, [chunk])`: Στην κατανομή dynamic οι επαναλήψεις χωρίζονται σε κομμάτια (chunks) και κάθε thread που ολοκληρώνει ένα chunk παίρνει το **επόμενο διαθέσιμο chunk**
    - Χρησιμοποιήτε όταν οι εργασίες μπορεί να είναι ακανόνηστες ή διαφορετικής διάρκειας, καθώς δίνει ευελιξία στο σύστημα για να εκτελούνται οι επαναλήψεις ανάλογα μα την προοδευτική ολοκλήρωση των threads.
- **guided** `schedule(guided, [chunk])`: Παρόμοιο με το dynamic, αλλά κομμάτια αρχικά ειναι μεγαλύτερα και στην συνέχεια μικραίνουν καθώς οι επαναλήψεις ολοκληρώνονται. 
    - Tο `guided` χρησιμοποιείται όταν οι επαναλήψεις έχουν σημαντική **διαφορετική διάρκεια** και θέλουμε οι πιο μεγάλες εργασίες να ανατίθενται πρώτες, ώστε τα μικρότερα κομμάτια να εκτελούνται σταδιακά  
    - `chunk`: Το μέγεθος του αρχικού κομματιού (chunk). Αν δεν καθοριστεί γίνεται το αρχικό chunk το μέγεθος της υπόλοιπης εργασίας.
- **runtime** `schedule(runtime)`: Ο αλγόρυθμος κατανομής εργασίας καθορίζεται από το **Unix Enviroment** τη στιγμή που ξεκινάει το πρόγραμμα.
    - Χρησιμοποιώντας την μεταβλητή περιβάλλοντος `OMP_SCHEDULE`, μπορείτε να ρυθμίσετε την πολιτική scheduling κατά την εκτέλεση του προγράμματος χωρίς να αλλάξετε τον κώδικα.
    - Το πρόγραμμα μπορεί να εκτελείται με διαφορετικές πολιτικές scheduling ανάλογα με το περιβάλλον, μπορούμε να το ορίσουμε με: `export OMP_SCHEDULE = "static,4";`

## Μοντέλο Μνήμης στο OpenMP
- **Coherence**: Συνεπής κατάσταση μεταξύ αντιγραφών μίας διέυθυνσης μνήμης.
    
- **Consistency**: Καθορίζει τη σειρά με την οποία γίνονται εγγραφές στη μνήμη
- **Weak Consistency**: Εγγυήσεις μόνο σε σημεία συγχρονισμού
